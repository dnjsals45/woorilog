# Permissions

이 문서는 새 V1의 공동 장부 권한과 개인 거래 공개 범위를 정의합니다. 제품 정책은 [V1 Scope](../product/v1-scope.md), 응답 필드 규칙은 [API Contract](./api-contract.md)를 따릅니다.

## 접근 상태

장부 접근은 역할만으로 판단하지 않고 참여 상태를 함께 봅니다.

| 상태 | 설명 | 기본 접근 |
| --- | --- | --- |
| `ACTIVE_OWNER` | 현재 공동 장부 소유자 | 전체 운영 권한 |
| `ACTIVE_MEMBER` | 현재 공동 장부 멤버 | 초대·내보내기·소유권 이전을 제외한 운영 권한 |
| `FORMER_MEMBER` | 탈퇴 또는 내보내기된 과거 참여자 | 참여 기간 읽기 전용 |
| `NON_MEMBER` | 참여 이력이 없는 사용자 | 공개 초대 확인 외 접근 불가 |

개인 장부는 소유자만 접근합니다.

## 장부 관리

| 동작 | Owner | Member | Former member |
| --- | --- | --- | --- |
| 장부·활성 멤버 조회 | 가능 | 가능 | 참여 기간 조회에 필요한 최소 정보만 가능 |
| 장부 이름 변경 | 가능 | 가능 | 불가 |
| 초대 링크 생성·취소 | 가능 | 불가 | 불가 |
| 소유권 이전 | 기존 멤버에게 가능 | 불가 | 불가 |
| 멤버 내보내기 | 가능 | 불가 | 불가 |
| 본인 탈퇴 | 소유권 이전 후 가능 | 가능 | 해당 없음 |
| 공동 장부 보관·삭제 | V1 미지원 | V1 미지원 | V1 미지원 |

- 소유권 이전, 탈퇴, 내보내기는 활성 멤버십을 잠그고 한 트랜잭션에서 처리합니다.
- 탈퇴·내보내기 시 예약 거래가 모두 일시정지된 뒤 멤버십을 종료합니다.
- 과거 상대방이 있는 장부에는 그 사용자만 다시 초대할 수 있습니다.

## 예산

| 동작 | 본인 개인 할당 | 상대방 개인 할당 | 공동 할당 | 예비비 |
| --- | --- | --- | --- | --- |
| 상위 금액 조회 | 가능 | 가능 | 가능 | 가능 |
| 상위 금액 변경 | 가능 | 가능 | 가능 | 이동으로만 변경 |
| 대분류 예산 조회·변경 | 본인만 | 불가 | 두 활성 멤버 | 해당 없음 |
| 거래 차감 | 본인만 | 불가 | 두 활성 멤버 | 직접 차감 불가 |
| 상세 거래 조회 | 본인 전체 | 공유된 거래만 | 전체 | 해당 없음 |

- 상대방 개인 할당의 총액·사용액·잔액은 예산 상세에서만 반환합니다.
- 홈, 최근 거래와 분석에는 상대방 개인 할당을 포함하지 않습니다.
- 예비비 이동 대상은 공동 할당과 두 사람의 개인 할당 전부입니다. 상대가 부탁하거나 한 사람이 예산을 도맡는 경우가 있어 본인 것만 허용하지 않습니다. 이동 기록이 남고 두 사람 모두 알림을 받습니다.
- 과거 멤버는 본인이 참여한 기간의 본인 할당과 공동 할당을 읽을 수 있지만 수정할 수 없습니다.
- 공동 장부는 소유자가 삭제할 수 있습니다. 단 현재 함께 쓰는 활성 멤버가 없어야 합니다. 나가기는 장부를 남기고 빠지는 것이고, 삭제는 장부 자체를 없애는 것이라 다릅니다.
- 과거 멤버가 있던 장부도 삭제할 수 있습니다. 삭제하면 그 사람의 읽기 전용 접근도 사라지므로 확인 화면에서 이름과 함께 알리고 장부 이름을 입력받습니다.
- 삭제된 장부의 초대 링크는 `LEDGER_DELETED`(410)로 응답합니다. 만료와 구분해야 초대받은 사람이 링크를 다시 받으러 가지 않습니다.

## 거래

| 거래 범위 | 생성 | 조회 | 수정·삭제 | 공개 설정 |
| --- | --- | --- | --- | --- |
| 본인 개인 할당 | 본인 | 본인 전체, 상대방은 공유 건만 | 본인 | 본인 |
| 상대방 개인 할당 | 불가 | 공유 건만 | 불가 | 불가 |
| 공동 할당 | 두 활성 멤버 | 두 활성 멤버 | 두 활성 멤버 | 항상 공동 공개 |
| 개인 장부 | 소유자 | 소유자 | 소유자 | 해당 없음 |

- 공동 장부의 수입과 예산을 차감하지 않는 이체도 `PERSONAL` 또는 `SHARED` scope를 가지며 같은 조회·공개 규칙을 적용합니다.
- 공동 거래의 마지막 변경자와 변경 시각은 두 멤버에게 보입니다.
- 공유된 개인 거래의 결제수단 종류는 보일 수 있지만 카드 id·카드 이름 등 식별 정보는 숨깁니다.
- 탈퇴 후 남은 사용자는 탈퇴 전에 공유된 개인 거래만 계속 볼 수 있습니다. 공개 상태를 탈퇴 시점에 자동 확대하지 않습니다.
- 과거 멤버는 본인이 기록한 개인 거래와 참여 기간의 공동 거래만 읽을 수 있습니다.

## 카테고리와 예약 거래

- 대분류는 시스템이 고정하며 활성 멤버도 생성·수정·삭제할 수 없습니다. 대분류에 대해 사용자가 할 수 있는 것은 장부별 표시·숨김뿐입니다.
- 활성 공동 장부 멤버는 장부 소분류를 생성·이름 변경·삭제할 수 있습니다.
- 개인 대분류 예산은 대상 사용자만 관리하고 공동 대분류 예산은 두 멤버가 관리합니다.
- 예약 거래는 차감 대상 할당을 수정할 권한이 있는 사용자만 생성합니다.
- 탈퇴·내보내기로 일시정지된 예약 거래는 남은 활성 멤버가 본인 또는 공동 할당을 대상으로 할 때만 재개할 수 있습니다.

## 알림

- 공동 예산·공동 대분류 알림은 두 활성 멤버에게 보냅니다.
- 개인 할당·개인 대분류 알림은 대상 사용자에게만 보냅니다.
- 기간 전체 예산 또는 멤버 할당 변경은 변경하지 않은 상대방에게 알립니다.
- 내보내기 알림은 내보내진 사용자에게, 자동 거래 일시정지 알림은 남은 사용자에게 보냅니다.

## API 강제 규칙

- 모든 ledger 하위 API는 path의 `ledgerId`와 인증 사용자의 접근 상태를 먼저 확인합니다.
- resource id만 받는 API도 resource가 속한 ledger의 권한을 다시 확인합니다.
- 목록과 집계 쿼리에서 권한 필터를 적용하며, 조회 후 DTO에서만 필드를 지우는 방식에 의존하지 않습니다.
- 존재하지만 볼 수 없는 거래는 정보 노출을 막기 위해 `404 RESOURCE_NOT_FOUND`로 응답합니다.
- 수정 권한이 없는 것으로 알려진 공동 자원에는 `403 FORBIDDEN`을 사용합니다.
- batch 요청은 모든 항목을 먼저 검증하고 하나라도 권한이 없으면 전체 요청을 실패시킵니다.
