# Privacy

이 문서는 새 V1에서 개인 거래, 결제 수단과 업로드 이미지가 노출되는 범위를 정의합니다. 권한 판단은 [Permissions](./permissions.md)를 원본으로 사용합니다.

## 데이터 분류

| 데이터 | 기본 보임 |
| --- | --- |
| 개인 가계부 | 소유자만 |
| 공동 예산 거래 | 두 활성 멤버 |
| 개인 예산 거래 | 기록자만, 거래별 공유 가능 |
| 개인 예산 합계 | 두 활성 멤버의 예산 상세 |
| 개인 카테고리 예산·분석 | 대상 사용자만 |
| 결제 수단 종류 | 거래 조회 권한이 있는 사용자 |
| 카드 id·카드 이름 등 식별 정보 | 결제한 사용자만 |
| 영수증·카드사 앱 이미지 | 업로드 사용자와 처리 작업만 |
| 알림·알림 설정 | 수신 사용자만 |

## 개인 거래 공유

- 개인 예산 거래의 기본값은 나만 보기입니다.
- 가계부별 전체 공유를 켜면 기존 개인 거래를 공유하고 이후 거래 기본값도 함께 보기로 바꿉니다.
- 전체 공유를 꺼도 기존 거래 보임 상태는 유지하고 이후 기본값만 나만 보기로 바꿉니다.
- 사용자는 거래별로 보임 상태를 다시 바꿀 수 있습니다.
- 공유 상태 변경은 거래 소유자만 수행합니다.
- 상대방이 공유 거래를 볼 수 있어도 수정·삭제할 수 없습니다.

## 탈퇴와 내보내기

- 멤버십 참여 구간을 보존해 과거 읽기 범위를 계산합니다.
- 탈퇴한 사용자는 본인이 참여한 기간의 본인 거래와 공동 거래를 읽기 전용으로 봅니다.
- 남은 사용자는 공동 거래와 탈퇴 전에 함께 보기였던 상대방 개인 거래만 봅니다.
- 나만 보는 거래는 탈퇴·내보내기·소유권 이전으로 보이게 되지 않습니다.
- 재참여해도 과거에 나만 보던 거래를 자동으로 보이게 하지 않습니다.

## 이미지와 OCR

- 업로드 이미지는 거래 후보 생성 목적에만 사용하며 거래 레코드에 원본을 직접 포함하지 않습니다.
- 후보 저장 또는 세션 만료 후 원본과 중간 산출물은 운영 보존 정책에 따라 제거할 수 있는 별도 저장소에 둡니다.
- API와 로그에는 이미지의 base64, OCR 전체 원문, 카드번호·승인번호 같은 민감 값을 남기지 않습니다.
- 중복 판정용 식별자가 필요하면 원문 대신 정규화한 hash 또는 제한된 식별자를 저장합니다.
- 제외된 저신뢰 결과는 후보 내용을 반환하지 않고 제외 건수와 일반화한 사유만 반환합니다.

## 로그와 오류

- access token, refresh token, OAuth code, 초대 token, 업로드 원본과 개인 거래 메모를 로그에 남기지 않습니다.
- 초대 token은 원문이 아니라 hash를 저장합니다.
- 권한 없는 resource 조회는 존재 여부를 드러내지 않도록 `404 RESOURCE_NOT_FOUND`를 사용합니다.
- 서버 오류 응답에는 내부 exception message, SQL, 외부 OCR 응답을 포함하지 않습니다.

## 삭제와 보존

- 사용자가 거래를 삭제하면 집계·검색·활동 기록에서 제거하고 예약 occurrence 연결도 정리합니다.
- 공동 가계부는 지금 함께 쓰는 사람이 없을 때 소유자가 삭제할 수 있습니다. 삭제하면 과거 멤버의 읽기 전용 조회도 사라지므로, 확인 화면에서 그 사실을 이름과 함께 알리고 가계부 이름을 입력받습니다.
- 카테고리 삭제는 비활성화이며 과거 거래 스냅샷은 유지합니다.
- 알림은 가계부의 다음 예산 기간 시작 시 사용자 목록에서 제거하되, 운영 감사 보존이 필요하면 사용자 조회 데이터와 분리합니다.
- 실제 보존 기간과 백업 삭제 주기는 배포·법적 요구가 확정될 때 운영 문서에서 정합니다. 이 문서는 미확정 기간을 정책으로 가정하지 않습니다.

## 검증 체크리스트

- 상대방이 나만 보는 거래가 목록·검색·홈·분석·알림 payload에 포함되지 않습니다.
- 공유 거래 응답에서 카드 식별 정보가 제거됩니다.
- 이전 멤버는 참여하지 않은 기간의 가계부 데이터를 조회할 수 없습니다.
- OCR 원본과 token이 애플리케이션 로그에 나타나지 않습니다.
- 캐시 key와 TanStack Query invalidation이 사용자와 가계부를 구분해 다른 사용자의 데이터를 재사용하지 않습니다.
