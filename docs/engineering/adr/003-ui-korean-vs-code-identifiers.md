# UI 한국어와 코드 식별자를 분리한다

제품 용어를 더 친근한 한국어로 정리하면서, 바꾸는 범위를 **사용자에게 보이는 문구와 `docs/**`** 로
한정하고 Kotlin 엔티티명·DB 테이블/컬럼·API 필드명은 그대로 두기로 했습니다.
그 결과 화면의 `예산 나누기`는 코드에서 `BudgetAllocation`이고, 화면의 `자동 기록`은 `ScheduledPlan`입니다.
두 열을 잇는 표는 [`CONTEXT.md`](../../../CONTEXT.md)가 갖습니다.

## Considered Options

**코드·DB까지 개명한다.** `budget_allocations` → 새 이름처럼 Flyway migration, 엔티티, repository,
service, DTO, 프론트 API 타입까지 한 줄로 이어지는 변경이 필요합니다. 이걸 다 해도 **사용자가 보는 화면은
한 글자도 바뀌지 않습니다.** 친근함은 사용자를 향한 목표인데 이 안은 사용자에게 도달하지 못합니다.

**신규 V1 코드만 개명한다.** 같은 개념이 신·구 두 이름으로 코드에 공존하게 됩니다.
용어 정리로 없애려던 바로 그 상태를 코드 쪽에 새로 만드는 셈이라 버렸습니다.

## Consequences

- 영어 식별자와 한국어 문구에 **서로 다른 기준**을 적용합니다. 코드 이름은 친근할 필요 없이
  모호하지 않기만 하면 되고, UI 문구는 정확하기만 해서는 안 되고 읽혀야 합니다.
- 한 칸 어긋나는 지점이 하나 있습니다. 한국어 `카테고리`는 코드의 `LedgerCategoryGroup`이고,
  코드의 `category` / `LedgerCategory`는 한국어로 `세부 카테고리`입니다. `CONTEXT.md`에 명시했습니다.
- 코드를 읽다 만난 이름의 한국어를 찾으려면 `CONTEXT.md`를 한 번 거쳐야 합니다.
  이 점프를 없애려면 위에서 버린 선택지로 돌아가야 하므로, 비용을 알고 받아들인 것입니다.
