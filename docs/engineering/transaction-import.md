# Transaction Import

이 문서는 영수증 사진과 카드사 앱 캡처에서 여러 거래 후보를 만들고 검토 후 저장하는 V1 기준입니다. HTTP 필드는 [API Contract](./api-contract.md)를 따릅니다.

## 입력과 세션

- 입력 종류는 `RECEIPT`, `CARD_APP_SCREENSHOT`입니다. 한 요청에 영수증과 카드앱 캡처를 섞어 올릴 수 있도록 **이미지별로** 지정합니다(`sourceTypes`는 `images[]`와 같은 개수·순서).
- 한 요청에서 여러 PNG/JPEG 이미지를 받을 수 있으며 허용 크기와 장수는 서버 설정으로 제한하고 API 오류에 현재 제한을 반환합니다.
- 이미지는 한 사용자의 한 가계부에 속한 import session으로 묶습니다.
- OCR 결과를 자동 저장하지 않고 preview와 명시적 save를 분리합니다.
- session은 짧은 유효기간을 가지며 저장 성공 또는 만료 뒤 다시 사용할 수 없습니다.

## 후보 생성

후보로 노출하려면 다음 필수값을 신뢰할 수 있게 추출해야 합니다.

- 거래 날짜
- 양수 금액
- 사용처

카테고리와 결제 수단은 필수 인식값이 아닙니다. 카테고리를 추천하지 못하면 미분류로 둡니다.

필수값이 없거나 threshold보다 낮은 결과는 후보 내용을 노출하지 않고 `omittedCount`와 일반화한 사유만 제공합니다. 일부 결과가 제외돼도 정상 후보의 검토와 저장은 계속합니다.

## 기본값과 추천

- 공동 가계부 후보는 업로드 사용자의 현재 기간 개인 예산을 기본 차감 대상으로 사용합니다.
- 개인 가계부 후보는 소유자의 개인 예산을 사용합니다.
- 상대방 개인 예산은 선택지로 반환하지 않습니다.
- 사용처 추천과 카테고리 추천은 `(userId, ledgerId, normalizedMerchant)` 범위의 확정 거래만 사용합니다.
- 삭제된 세부 카테고리와 상대방의 거래는 추천 근거에서 제외합니다.

## 중복 판단

현재 구현은 정규화한 **날짜·금액·사용처(소문자화 후 영숫자만 남긴 문자열)** 완전 일치로 같은 session의 다른 후보, 그리고 같은 가계부의 기존 확정 거래와 비교합니다.

- 중복 의심은 `duplicateSuspected=true`와 `duplicateReason="DATE_AMOUNT_MERCHANT"`로 표시합니다.
- 기존에 저장된 거래와 겹치면 `duplicateTransactionId`에 그 거래의 id를 채웁니다. 같은 업로드 배치의 다른 후보와만 겹치는 경우(아직 저장되지 않은 후보끼리의 충돌)에는 `duplicateTransactionId`가 `null`입니다.
- 중복 후보는 `selectedByDefault=false`, 정상 후보는 `true`입니다.
- 후보나 기존 거래를 자동 삭제하지 않습니다.
- 정상적인 반복 결제라면 사용자가 후보를 다시 선택해 저장할 수 있습니다.

## 검토와 저장

- 사용자는 후보별 날짜, 금액, 사용처, 카테고리와 차감 예산을 수정할 수 있습니다.
- 여러 후보의 카테고리 또는 차감 예산을 일괄 변경할 수 있습니다.
- 저장 요청은 선택한 최종값 전체를 보내고 서버는 일반 거래 validation과 권한을 다시 검사합니다.
- 한 session 저장은 원자적입니다. 하나라도 잘못되면 어떤 후보도 저장하지 않습니다.
- 같은 session의 재전송은 중복 거래를 만들지 않습니다.
- 저장 성공 응답은 생성된 거래 id와 후보 id mapping을 반환합니다.

## 원본과 로그

- 이미지와 OCR 원문은 거래 레코드에 포함하지 않습니다.
- 카드번호, 승인번호와 token은 원문으로 로그에 남기지 않습니다.
- 저장 또는 만료 후 원본 정리는 [Privacy](./privacy.md)의 보존 원칙을 따릅니다.

## 실패 처리

| 상황 | 처리 |
| --- | --- |
| 지원하지 않는 파일 | 요청 전체 `400 UNSUPPORTED_MEDIA` |
| 제한 초과 | 요청 전체 `413 UPLOAD_LIMIT_EXCEEDED` |
| 일부 이미지 인식 실패 | 정상 후보와 제외 건수 반환 |
| 모든 결과 저신뢰 | 빈 후보와 제외 건수 `200` |
| session 만료 | `410 IMPORT_SESSION_EXPIRED` |
| 저장 권한 변경 | `403 FORBIDDEN`, 저장 없음 |
| 후보 validation 실패 | `400 INVALID_IMPORT_CANDIDATE`, 저장 없음 |

## 검증

- 여러 이미지 후보가 하나의 session과 목록으로 합쳐집니다.
- 저신뢰 결과 내용은 응답에 나타나지 않습니다.
- 사용자·가계부가 다른 거래는 추천 근거가 되지 않습니다.
- 중복 후보는 기본 선택 해제되지만 사용자가 저장할 수 있습니다.
- batch save의 권한·validation·재시도는 원자성과 멱등성을 유지합니다.
