# V1 Scope

이 문서는 우리로그 V1의 기능 범위와 제품 정책을 큰 기능 영역별로 정리하는 원본입니다.
구체적인 사용 순서는 [User Flows](./user-flows.md), 화면과 경로는 [Information Architecture](../design/information-architecture.md)에서 확인합니다.
현재 구현이 이 문서와 다르면 이 문서를 목표로 삼아 API 계약, 도메인 모델, 화면 명세와 테스트를 함께 갱신합니다.

## 시작과 장부 관리

### 최초 가입과 개인 장부

- 신규 사용자는 카카오로 로그인합니다.
- 최초 가입 과정에서 서비스 닉네임을 확정합니다. 카카오 닉네임을 기본값으로 제공하고 사용자가 수정할 수 있습니다.
- 신규 사용자에게 기본 개인 장부를 자동 생성합니다.
- 기본 개인 장부는 항상 장부 목록에 표시하며 숨기거나 삭제할 수 없습니다.
- 별도 튜토리얼은 제공하지 않고 화면의 빈 상태와 안내 문구로 다음 행동을 안내합니다.
- 일반 경로로 로그인하면 닉네임 확정 후 기본 개인 장부로 진입합니다.
- 초대 링크를 통해 로그인하면 닉네임 확정 후 원래의 초대 확인 화면으로 돌아갑니다.

### 공동 장부 생성

- 한 사용자는 여러 공동 장부를 만들거나 참여할 수 있습니다.
- 각 공동 장부는 `OWNER`와 초대받은 `MEMBER`를 합쳐 최대 두 명이 사용합니다.
- 공동 장부 생성 시 장부 이름, 기간 전체 예산과 반복할 예산 기간을 필수로 설정합니다.
- 장부 이름에는 자동 기본값을 제공하지 않습니다.
- 예산 기간 시작일은 `1일`부터 `28일` 또는 `말일` 중에서 정합니다.
- 다음 예산 기간 시작일의 직전일까지를 한 기간으로 계산합니다. 예를 들어 시작일이 10일이면 10일부터 다음 달 9일까지입니다.
- 예산 기간 중간에 공동 장부를 만들어도 남은 날짜에 비례해 줄이지 않고 현재 예산 기간의 전체 금액을 설정합니다.
- 생성 시점에는 상대방이 없으므로 멤버별 할당과 공동 예산을 정하지 않고 기간 전체 예산만 저장합니다.
- 생성한 사용자는 `OWNER`가 되며 장부 생성 후 상대방 초대로 이어집니다.

### 상대방 초대

- 공동 장부 초대는 링크 공유만 지원합니다.
- 가입 사용자 검색과 직접 초대는 제공하지 않습니다.
- 초대 링크는 `OWNER`만 생성할 수 있고 생성 후 30분 동안 유효합니다.
- 공동 장부마다 하나의 활성 초대 링크만 유지합니다.
- 새 링크를 생성하면 아직 유효한 이전 링크도 즉시 무효화합니다.
- 초대받은 사용자가 수락하면 링크는 즉시 만료합니다.
- 로그인하지 않은 사용자가 링크를 열면 카카오 로그인 후 같은 초대 확인 화면으로 돌아옵니다.
- 로그인만으로 참여시키지 않고 장부 이름과 초대한 사용자를 확인한 뒤 명시적으로 수락하게 합니다.
- 사용자가 초대를 거절하면 해당 링크를 종료합니다.
- 만료, 교체, 거절 또는 취소된 링크는 사용할 수 없으며 `OWNER`는 즉시 새 링크를 생성할 수 있습니다.
- 이미 두 명이 참여했거나 사용자가 이미 해당 장부의 멤버라면 참여시키지 않고 이유를 안내합니다.

### 참여 완료

- 초대를 수락하면 해당 공동 장부를 현재 장부로 자동 선택하고 공동 장부 대시보드로 이동합니다.
- 새 `MEMBER`는 참여 이전에 저장된 공동 예산과 공동 거래 내역도 조회할 수 있습니다.
- 상대방이 아직 참여하지 않았다면 대시보드에서 초대 완료를 먼저 안내합니다.
- 두 사람이 참여했지만 예산 배분이 없다면 예산 설정을 첫 번째 행동으로 안내합니다.
- 예산 설정 이후 거래가 없다면 빠른 기록과 영수증·카드사 앱 캡처 가져오기를 안내합니다.

### 역할과 권한

| 기능 | `OWNER` | `MEMBER` |
| --- | --- | --- |
| 예산 배분 조회·변경 | 가능 | 가능 |
| 본인 할당 예산 거래 기록 | 가능 | 가능 |
| 공동 예산 거래 기록 | 가능 | 가능 |
| 상대방 할당 예산 거래 변경 | 불가 | 불가 |
| 초대 링크 관리 | 가능 | 불가 |
| 기존 멤버에게 소유권 이전 | 가능 | 소유권 이전 후 `OWNER`가 됨 |
| 멤버 내보내기 | 가능 | 불가 |
| 공동 장부 탈퇴 | 불가 | 가능 |

### 탈퇴와 내보내기

- `MEMBER`는 공동 장부에서 직접 탈퇴할 수 있습니다.
- 탈퇴 전에 장부 이름과 탈퇴 후 변경되는 권한을 보여주는 강한 확인 절차를 거칩니다.
- 탈퇴한 사용자는 본인이 참여했던 예산 기간의 장부를 읽기 전용으로 조회할 수 있습니다.
- `OWNER`가 멤버를 내보낸 경우에도 내보낸 사용자는 참여했던 기간을 읽기 전용으로 조회할 수 있습니다.
- 멤버를 내보내면 해당 사용자에게 앱 내부 알림을 보냅니다.
- `OWNER`가 탈퇴하려면 먼저 기존 `MEMBER`에게 소유권을 이전해야 합니다.
- 소유권을 이전한 사용자는 `MEMBER`가 된 뒤 같은 탈퇴 절차를 진행합니다.
- 한 사용자가 탈퇴하거나 내보내지면 공동 장부의 고정비, 할부와 반복 거래 자동 등록을 모두 일시정지합니다.
- 자동 등록을 일시정지한 사실을 남은 사용자에게 앱 내부 알림으로 안내합니다.
- 남은 사용자는 필요한 자동 거래만 다시 활성화할 수 있습니다.

### 탈퇴 후 데이터와 재참여

- 탈퇴한 사용자는 본인의 개인 거래와 본인이 참여했던 기간의 공동 거래를 조회할 수 있습니다.
- 남은 사용자는 공동 거래와 탈퇴 전에 상대방이 공유한 개인 거래만 조회할 수 있습니다.
- 탈퇴 전 비공개였던 개인 거래는 이후에도 상대방에게 공개하지 않습니다.
- 탈퇴했던 동일한 상대방은 새 초대 링크를 수락해 기존 공동 장부에 다시 참여할 수 있습니다.
- 전혀 다른 사용자는 탈퇴자가 있던 기존 장부에 초대할 수 없으며 새 공동 장부를 만들어야 합니다.
- 첫 버전에는 탈퇴 전 거래 내역 파일 내려받기를 제공하지 않고 읽기 전용 조회만 제공합니다.
- 첫 버전에는 공동 장부 보관 상태를 제공하지 않습니다.
- 공동 장부의 영구 삭제는 제공하지 않습니다.

## 예산 설정

### 예산 구성

커플이나 부부는 한 예산 기간에 운영할 전체 금액을 다음과 같이 나눕니다.

- 멤버 A 할당 예산
- 멤버 B 할당 예산
- 함께 사용하는 공동 예산
- 필요할 때 사용할 수 있는 예비비

예를 들어 기간 전체 예산이 100만 원이면 A 할당 20만 원, B 할당 20만 원, 공동 예산 50만 원, 예비비 10만 원으로 나눌 수 있습니다.

### 첫 예산 배분

- `OWNER`는 상대방을 초대하기 전에 기간 전체 예산과 예산 기간을 설정할 수 있습니다.
- 상대방이 참여한 뒤 두 사용자가 각자의 할당 예산과 공동 예산을 함께 정합니다.
- 배분 합계가 기간 전체 예산보다 작으면 차액을 예비비로 자동 계산합니다.
- 예를 들어 전체 예산이 200만 원이고 배분 합계가 160만 원이면 예비비는 40만 원입니다.
- 배분 합계가 전체 예산보다 크면 전체 예산을 해당 합계로 높일지 확인합니다.
- 증액을 확인하면 전체 예산을 변경하고 예비비를 0원으로 저장합니다.
- 증액을 확인하지 않으면 저장하지 않고 금액을 다시 조정하게 합니다.
- 예산 기간 중간에 참여해도 현재 예산 기간 전체를 기준으로 하며 비례 계산하지 않습니다.

### 예비비

- 예비비는 `기간 전체 예산 - 멤버별 할당 예산 - 공동 예산`으로 자동 계산합니다.
- 예비비에서는 거래 금액을 바로 차감하지 않습니다.
- 예비비가 필요하면 본인 할당 예산이나 공동 예산으로 옮긴 뒤 사용합니다.
- 상대방 할당 예산은 예비비 이동 대상이 아닙니다. 상대방 잔액을 임의로 바꿀 수 있게 하는 것은 감시가 아니라 공유라는 원칙과 어긋납니다.
- 예비비 이동 기록은 두 사용자 모두 확인할 수 있습니다.
- 예산 설정 화면에서 예비비를 별도 금액으로 표시합니다.

### 예산과 거래 연결

- 각 지출은 차감할 예산에 연결합니다.
- 공동 목적의 지출은 결제자나 결제수단과 관계없이 공동 예산에서 차감합니다.
- 개인 목적의 지출은 해당 멤버의 할당 예산에서 차감합니다.
- 결제자와 결제수단은 거래를 설명하는 정보이며 차감할 예산을 결정하지 않습니다.
- 두 사용자는 서로의 할당액을 보고 함께 변경할 수 있습니다.
- 각 사용자는 본인 할당 예산과 공동 예산에만 거래를 기록할 수 있습니다.
- 상대방 할당 예산을 차감하는 거래는 생성·수정·삭제할 수 없습니다.

### 다음 예산 기간 준비

- 사용자는 다음 예산 기간이 시작되기 전에 전체 예산, 멤버별 할당, 공동 예산과 대분류 예산을 미리 설정할 수 있습니다.
- 다음 기간 시작 3일 전까지 예산이 설정되지 않았다면 예산 설정 권한이 있는 사용자에게 앱 내부 안내 알림을 보냅니다.
- 안내 알림에서는 현재 기간의 예산 설정을 그대로 복사하거나 다음 기간 예산을 직접 설정할 수 있습니다.
- 공동 장부에서 한 사용자가 다음 기간 예산을 설정하면 해당 장부의 다음 기간 준비가 완료된 것으로 처리합니다.
- 사용자가 안내 알림을 확인하지 않거나 별도로 설정하지 않으면 다음 기간 시작 시 현재 기간의 전체 예산, 멤버별 할당, 공동 예산과 대분류 예산을 자동으로 복사합니다.
- 현재 기간에 남은 개인 할당 예산, 공동 예산과 예비비는 실제 잔액으로 이월하지 않습니다.
- 현재 기간의 초과 사용액도 다음 기간 예산에서 자동 차감하지 않습니다.
- 남은 금액과 초과액은 종료된 기간의 결과로만 보존합니다.
- 고정비, 할부와 반복 거래는 다음 기간에도 이어지며 예정액에 자동 반영합니다.

### 예산 설정 변경

- 현재 기간의 예산을 변경할 때 `이번 기간만 변경` 또는 `이번 기간과 이후 기간의 기본값도 변경` 중 하나를 선택합니다.
- 예산 기간 시작일을 변경하면 이미 지난 기간의 범위는 유지하고 다음 기간부터 새 시작일을 적용합니다.

### 지난 기간

- 새 기간이 시작된 뒤에도 이전 기간의 거래를 추가·수정·삭제할 수 있습니다.
- 과거 거래가 변경되면 해당 기간의 대시보드와 분석을 다시 계산하지만 새 예산 알림은 생성하지 않습니다.
- 첫 버전에는 사용자가 기간을 마감해 수정을 잠그는 기능을 제공하지 않습니다.
- 기간 종료 요약에는 공동 예산과 본인 예산의 사용액·잔액·초과액, 대분류별 지출, 미분류 거래 개수와 다음 기간에 이어지는 고정비·할부를 표시합니다.
- 상대방 개인 예산의 세부 내역은 본인의 기간 종료 요약에서 제외합니다.

## 거래 입력

### 거래 종류

- 첫 버전에서는 `지출`, `수입`, `계좌이체`를 거래 내역에 기록합니다.
- 환불은 첫 버전에 포함하지 않습니다.
- 추후 환불을 지원할 때는 별도의 환불 거래를 직접 입력하기보다 기존 거래를 선택해 취소하고 원래 반영 상태로 되돌리는 방식을 우선합니다.
- 지출은 본인 할당 예산 또는 공동 예산에서 차감합니다.
- 수입은 수입 내역과 통계에만 반영하며 설정된 전체 예산을 자동으로 늘리지 않습니다.
- 수입을 가용 예산에 반영하려면 사용자가 예산 설정에서 직접 전체 예산을 변경합니다.
- 계좌이체를 기록할 때 `내 계좌 간 이체`, `다른 곳으로 송금`, `외부에서 입금` 중 하나를 선택합니다.
- `내 계좌 간 이체`는 예산 사용액과 수입·지출 통계에서 제외합니다.
- `다른 곳으로 송금`은 지출로 기록하고 선택한 예산에서 차감합니다.
- `외부에서 입금`은 수입으로 기록하되 전체 예산은 자동으로 늘리지 않습니다.
- 계좌이체에도 카테고리를 지정하고 상대 계좌나 상대방 정보는 사용처에 입력합니다.
- 계좌이체를 위해 별도의 보낸 곳·받은 곳 입력란은 두지 않습니다.

### 빠른 기록

- 대시보드와 주요 화면에서 빠른 기록을 바로 시작할 수 있습니다.
- 빠른 기록 버튼을 누르면 금액 키패드를 바로 엽니다.
- 빠른 기록에서는 금액, 사용처와 카테고리를 필수로 입력합니다.
- 날짜는 오늘을 기본으로 설정하고 사용자가 변경할 수 있습니다.
- 거래 시간은 기록할 수 있지만 필수로 입력하지 않습니다.
- 메모와 결제수단은 선택 입력으로 둡니다.
- 공동 장부에서는 현재 사용자와 현재 장부에서 마지막으로 선택한 차감 예산을 기본값으로 기억합니다.
- 기억한 값이 없으면 현재 사용자의 할당 예산을 기본으로 선택합니다.
- 공동 목적의 지출이면 사용자가 공동 예산으로 변경합니다.
- 저장 전에 차감할 예산을 확인할 수 있어야 합니다.
- 상대방 할당 예산은 선택지로 제공하지 않습니다.
- 카드 지출은 일시불과 할부 여부를 선택할 수 있습니다.
- 기본 저장은 입력 화면을 닫고, `저장 후 계속 입력`을 선택하면 같은 입력 화면에서 다음 거래를 이어서 기록합니다.
- 사용처를 입력할 때 같은 사용자와 장부의 기존 사용처를 추천합니다.
- 동일한 사용처의 확정 거래가 있으면 과거 이력을 기준으로 카테고리도 함께 추천합니다.
- 빠른 기록에서는 추천 결과가 없더라도 사용자가 카테고리를 선택해야 저장할 수 있습니다.

### 일괄 가져오기

- 여러 장의 종이 영수증 사진을 한 번에 가져올 수 있습니다.
- 카드사 앱의 사용 내역 캡처에서 여러 거래 행을 후보로 만들 수 있습니다.
- 여러 이미지에서 만든 후보를 하나의 검토 목록으로 합칩니다.
- 하루에 거래가 20건이어도 입력 화면을 20번 열지 않고 한 번의 검토 흐름으로 저장할 수 있어야 합니다.
- 여러 거래 후보의 날짜, 금액, 사용처, 카테고리와 차감할 예산을 검토하고 필요한 항목만 수정합니다.
- 인식 결과를 자동 저장하지 않고 반드시 검토 화면을 거칩니다.
- 정상 인식된 후보는 기본 저장 대상으로 선택합니다.
- 중복 의심 후보는 기본 저장 대상에서 제외하고 빨간색 테두리와 안내 문구로 구분합니다.
- 여러 후보를 선택해 차감 예산이나 카테고리를 한 번에 변경할 수 있습니다.
- 날짜와 사용처는 후보별로 수정합니다.
- 저장할 후보를 선택해 한 번에 등록합니다.
- 마이데이터나 카드사 계정 기반 자동 수집은 이미지 가져오기 흐름이 안정된 이후의 장기 기획으로 둡니다.

### 가져오기 기본값

- 공동 장부로 가져온 후보는 업로드한 사용자의 할당 예산을 기본으로 선택합니다.
- 사용자는 공동 목적의 거래만 선택해 공동 예산으로 변경합니다.
- 여러 거래를 선택해 공동 예산으로 한 번에 변경할 수 있습니다.
- 상대방 할당 예산은 선택지로 제공하지 않습니다.
- 저장 전에 후보별 차감 예산을 확인할 수 있어야 합니다.

### 카테고리 추천

- 현재 사용자, 현재 장부와 사용처가 같은 확정된 과거 거래를 기준으로 카테고리를 추천합니다.
- 같은 공동 장부에서도 사용자별 추천 이력을 분리합니다.
- 같은 사용자의 개인 장부와 공동 장부 사이에서도 추천 이력을 분리합니다.
- 추천 카테고리는 후보에 표시하고 사용자가 직접 또는 일괄 수정할 수 있습니다.
- 수정해 저장한 카테고리는 이후 같은 사용처의 추천에 반영합니다.
- 신뢰할 수 있는 추천이 없으면 `미분류`로 표시하고 카테고리 없이도 저장할 수 있습니다.
- 저장한 `미분류` 거래는 나중에 모아서 분류할 수 있습니다.

### 중복 거래

- 같은 가져오기 안의 후보와 현재 장부에 이미 저장된 거래를 함께 비교합니다.
- 거래 날짜, 금액과 사용처가 같으면 중복 가능성이 있는 거래로 표시합니다.
- 카드 승인번호처럼 안정적으로 얻을 수 있는 식별자가 같으면 우선 사용합니다.
- 중복 의심 후보는 삭제하지 않고 기본 저장 대상에서 제외합니다.
- 정상적인 반복 결제라면 사용자가 다시 선택해 저장할 수 있습니다.
- 사용자의 확인 없이 기존 거래나 후보를 자동 삭제하지 않습니다.

### 인식 품질

- 거래 날짜, 금액과 사용처를 신뢰할 수 있게 인식한 거래만 후보로 표시합니다.
- 필수 정보가 누락되거나 인식 신뢰도가 낮은 결과는 불완전한 후보로 노출하지 않습니다.
- 인식하지 못한 거래가 있으면 후보 내용 대신 제외된 건수만 안내합니다.
- 사용자는 더 선명한 이미지나 필요한 영역만 다시 캡처해 가져올 수 있습니다.
- 일부 거래를 인식하지 못해도 정상 후보의 검토와 저장은 계속할 수 있습니다.
- 카테고리는 OCR 필수 정보가 아니며 추천할 수 없으면 `미분류` 규칙을 적용합니다.

### 수정과 삭제

- 본인 할당 예산에서 차감한 거래는 본인만 수정·삭제할 수 있습니다.
- 공동 예산에서 차감한 거래는 두 사용자 모두 수정·삭제할 수 있습니다.
- 공동 거래를 수정해도 상대방에게 별도 알림을 보내지 않습니다.
- 공동 거래의 변경 내역에는 변경한 사용자와 변경 시각을 남깁니다.
- 거래를 삭제하면 해당 거래가 반영한 예산 사용액을 즉시 되돌립니다.
- 삭제한 거래와 삭제 이력은 거래 내역과 활동 기록에 남기지 않습니다.

### 할부 거래

- 할부 거래는 전체 결제 금액과 할부 개월 수를 입력합니다.
- 전체 결제 금액을 할부 개월 수에 따라 나누고 각 회차 금액을 그 결제일이 속한 예산 기간에서 차감합니다.
- 예를 들어 120만 원을 12개월로 결제하면 매월 기본 원금 10만 원을 예산에 반영합니다.
- 할부 회차는 반복 거래 방식으로 자동 등록합니다.
- 사용자는 할부 거래에 매월 적용할 이자 금액을 설정할 수 있습니다.
- 이자가 있는 할부는 각 회차의 원금에 설정한 월 이자 금액을 더해 그 결제일이 속한 예산 기간에 반영합니다.
- 월 이자 금액을 0원으로 설정하면 무이자 할부로 처리합니다.
- 거래 상세에 전체 결제 금액과 `3/12회차` 같은 현재 회차를 표시합니다.

### 정기 거래와 고정비

- 반복 거래는 첫 버전에 포함합니다.
- 반복 주기는 매주, 매월과 매년을 지원합니다.
- 반복 거래는 예정일에 자동 등록합니다.
- 반복 수입은 첫 버전의 필수 요구 범위에 포함하지 않습니다.
- 사용자는 반복되는 지출을 등록하면서 고정비로 관리할지 선택할 수 있습니다.
- 고정비로 지정한 반복 지출은 일반 거래 목록과 별도로 모아 현재 고정비 구성과 합계 금액을 확인할 수 있어야 합니다.
- 반복 거래를 수정할 때는 `이번 거래와 이후 예정 거래 모두 변경`할지 사용자에게 확인한 뒤 적용합니다.
- 반복 거래를 중단하거나 삭제해도 이미 자동 등록된 과거 거래는 유지합니다.
- 매월 반복일이 해당 월에 없으면 그 달의 말일에 자동 등록합니다. 예를 들어 매월 31일 거래는 2월 28일 또는 29일에 등록합니다.

## 대시보드와 상세 조회

### 기준 기간

- 대시보드는 달력 월이 아니라 장부에 설정한 현재 예산 기간을 기준으로 집계합니다.
- 예산 기간 시작일이 10일이면 10일부터 다음 달 9일까지의 데이터를 표시합니다.
- 사용자는 이전 예산 기간으로 이동해 같은 형태의 과거 대시보드를 조회할 수 있습니다.
- 대시보드에 처음 진입하면 항상 현재 예산 기간을 표시합니다.

### 공동 장부 대시보드

- 공동 예산을 가장 먼저 강조합니다.
- 로그인한 사용자의 할당 예산을 공동 예산 다음에 표시합니다.
- 각 예산 카드에는 남은 금액을 가장 크게 표시하고 사용 금액, 전체 예산과 사용률을 함께 표시합니다.
- `현재 잔액`은 전체 예산에서 실제 등록된 지출을 뺀 금액입니다.
- `사용 가능액`은 현재 잔액에서 현재 예산 기간에 남아 있는 고정비와 할부 예정액을 뺀 금액입니다.
- 대시보드에서는 현재 잔액보다 사용 가능액을 강조합니다.
- 예산을 초과하면 남은 금액을 0원으로 제한하지 않고 음수 금액과 초과 상태를 표시합니다.
- 상대방의 할당 예산, 사용 금액과 남은 금액은 대시보드에 표시하지 않습니다.
- 예비비는 대시보드보다 예산 설정 화면에서 확인합니다.
- 수입은 예산과 분리된 이번 예산 기간의 합계로 간단히 표시하며 예산 금액에는 합산하지 않습니다.
- 최근 거래에는 공동 예산 거래와 로그인한 사용자의 개인 거래만 시간순으로 섞어서 표시합니다.
- 상대방 개인 거래는 공유 여부와 관계없이 대시보드의 최근 거래에서 제외합니다.
- 주간 예산 가이드는 알림 생성 후 다음 가이드가 생성될 때까지 대시보드에도 표시합니다.
- 작은 `+` 버튼에서 빠른 기록, 영수증 사진과 카드사 앱 캡처 중 입력 방식을 선택할 수 있습니다.

### 상세 조회

- 공동 예산이나 본인 예산 카드를 선택하면 전체·사용·남은 금액, 카테고리별 사용액, 날짜별 소비 흐름, 해당 예산의 거래 목록과 남은 고정비·할부를 표시합니다.
- 상대방의 할당 예산 전체 금액, 사용 금액과 남은 금액은 상세 화면에서 조회할 수 있습니다.
- 상대방 할당 예산의 개별 거래는 거래를 기록한 사용자가 공유한 경우에만 표시합니다.
- 본인 할당 예산 거래는 기본적으로 상대방에게 공개하지 않습니다.
- 사용자가 공동 장부 설정에서 본인 거래 전체 공유를 켜면 기존 개인 거래를 모두 공유하고 이후 새 거래도 공유를 기본값으로 설정합니다.
- 전체 공유를 켠 상태에서도 특정 거래를 다시 비공개로 변경할 수 있습니다.
- 전체 공유를 끄면 기존 거래의 공유 상태는 유지하고 이후 새 거래만 비공개를 기본값으로 설정합니다.
- 본인 할당 예산 거래를 기록한 사용자는 전체 공유 설정과 별도로 거래별 공유 여부를 선택하고 나중에 변경할 수 있습니다.
- 상대방이 공유한 거래는 금액, 날짜, 사용처, 카테고리와 메모를 조회할 수 있습니다.
- 공유한 거래의 결제수단 종류는 표시하지만 카드 식별 정보는 결제한 본인에게만 표시합니다.
- 공동 예산 거래는 별도의 공유 선택 없이 두 사용자 모두에게 표시합니다.
- 상대방이 공유한 개인 거래를 조회할 수 있어도 수정·삭제할 수는 없습니다.
- 대시보드에서 상대방 예산을 숨기는 것은 첫 화면의 정보 집중을 위한 정책이며, 상세 화면의 거래 공개 여부는 사용자의 공유 선택을 따릅니다.

### 거래 목록

- 전체 거래 내역은 달력 전환 없이 날짜순 목록으로 제공합니다.
- 사용처와 메모로 거래를 검색할 수 있습니다.
- 지출·수입·계좌이체, 카테고리, 공동·본인 예산, 일반·고정비·할부와 공유 여부로 필터링할 수 있습니다.
- 검색어와 여러 필터를 함께 적용할 수 있습니다.

### 빈 상태

- 상대방이 아직 참여하지 않았다면 초대 완료를 안내합니다.
- 두 사람이 참여했지만 예산 배분이 없다면 예산 설정을 첫 번째 행동으로 안내합니다.
- 예산 설정 후 거래가 없다면 빠른 기록과 거래 가져오기를 안내합니다.
- 별도 튜토리얼을 강제하지 않고 상태별 안내로 다음 행동을 제시합니다.

## 카테고리와 분석

### 카테고리 구조

- 카테고리는 장부별로 따로 관리합니다.
- 개인 장부와 각 공동 장부의 카테고리는 서로 영향을 주지 않습니다.
- 공동 장부의 카테고리는 두 사용자가 함께 사용하며 두 사용자 모두 생성·수정·삭제할 수 있습니다.
- 카테고리는 시스템이 정한 대분류와 장부별로 만드는 소분류의 2단계로 구성합니다.
- 대분류의 이름과 개수는 시스템이 고정하며 사용자가 생성·수정·삭제하지 않습니다.
- 사용하지 않는 대분류는 장부별로 숨길 수 있습니다.
- 사용자는 정해진 대분류 아래에 원하는 소분류를 생성할 수 있습니다.
- 같은 장부의 같은 대분류 안에는 이름이 같은 소분류를 중복 생성할 수 없습니다.
- 기본 소분류도 사용자 생성 소분류와 동일하게 이름을 변경하거나 삭제할 수 있습니다.
- 새 장부에는 다음 기본 카테고리를 제공합니다.

| 거래 유형 | 대분류 | 기본 소분류 |
| --- | --- | --- |
| 지출 | 식비 | 장보기, 외식, 배달, 카페·간식 |
| 지출 | 주거·생활 | 월세·관리비, 공과금, 통신, 생활용품 |
| 지출 | 교통·차량 | 대중교통, 택시, 주유, 주차·통행, 차량관리 |
| 지출 | 쇼핑·미용 | 의류, 미용, 전자기기, 기타 쇼핑 |
| 지출 | 건강 | 병원, 약국, 운동 |
| 지출 | 여가 | 문화, 취미, 여행, 모임 |
| 지출 | 교육 | 도서, 강의·학원 |
| 지출 | 금융 | 보험, 세금, 이자·수수료 |
| 지출 | 관계 | 경조사, 선물 |
| 지출 | 반려동물 | 사료·용품, 동물병원 |
| 지출 | 기타 | 기타 지출 |
| 수입 | 근로소득 | 급여, 상여 |
| 수입 | 기타수입 | 용돈, 금융수입, 중고거래, 기타 수입 |
| 계좌이체 | 이체 | 내 계좌 간 이체, 송금, 입금 |

- OCR에서 카테고리를 확정하지 못한 거래는 `미분류`로 저장합니다.
- 미분류 거래는 별도 목록과 개수 배지로 표시하고 여러 거래를 선택해 한 번에 분류할 수 있습니다.

### 거래 카테고리 스냅샷

- 거래를 저장할 때 선택한 대분류와 소분류 정보를 거래의 카테고리 스냅샷으로 저장합니다.
- 거래 조회와 분석은 현재 카테고리 정의를 실시간으로 연결하지 않고 거래에 저장된 스냅샷을 기준으로 합니다.
- 소분류의 이름을 변경하거나 삭제해도 이전 거래의 카테고리 이름과 분석 결과는 소급해 바뀌지 않습니다.
- 소분류 이름을 변경할 때 기본적으로 이후 거래부터 새 이름을 사용하고, 사용자가 `과거 거래에도 적용`을 선택하면 기존 거래의 해당 스냅샷도 함께 변경합니다.
- 삭제한 소분류는 새 거래에서 더 이상 선택할 수 없지만 이전 거래에는 그대로 표시합니다.
- 삭제한 소분류는 과거 사용처 기반 카테고리 추천에서도 제외합니다.
- 기존 거래의 카테고리를 직접 변경하면 해당 거래의 카테고리 스냅샷을 새 선택값으로 교체합니다.
- 카테고리 분석은 변경할 수 없는 대분류를 기준으로 집계하므로 소분류 이름 변경이나 삭제가 대분류 분석 결과에 영향을 주지 않습니다.

### 카테고리 예산

- 사용자는 소분류가 아닌 대분류별로 예산을 설정합니다.
- 공동 예산 안에서는 공동 대분류 예산을, 본인 할당 예산 안에서는 본인 대분류 예산을 설정합니다.
- 대분류 예산은 상위 예산을 나누는 세부 배분이며 전체 예산에 추가되는 금액이 아닙니다.
- 공동 대분류 예산은 두 사용자 모두 조회·변경할 수 있습니다.
- 본인 대분류 예산은 본인만 조회·변경하며 상대방에게 공개하지 않습니다.
- 대분류 예산 합계가 상위 예산보다 작으면 차액을 미배분 금액으로 표시합니다.
- 대분류 예산 합계가 상위 예산을 초과하면 상위 예산을 늘릴지 확인합니다.
- 증액을 확인하지 않으면 저장하지 않고 금액을 다시 조정하게 합니다.
- 대분류 예산을 초과해도 거래 저장을 제한하지 않습니다.
- 대분류 예산 사용률이 80%에 도달하거나 모두 사용·초과하면 해당 예산을 볼 수 있는 사용자에게 알립니다.

### 분석 범위

- 분석은 현재 선택한 장부의 데이터만 사용하며 개인 장부와 공동 장부를 합산하지 않습니다.
- 공동 장부 분석에는 공동 예산 거래와 로그인한 사용자의 개인 거래를 포함합니다.
- 분석 화면에서 `전체`, `공동 예산`, `내 예산`으로 범위를 전환할 수 있습니다.
- 상대방 개인 거래는 공유 여부와 관계없이 분석에서 제외합니다.
- 분석 기간은 달력 월이 아니라 장부에 설정한 예산 기간을 기준으로 합니다.
- 분석 첫 화면의 대표 지표는 총지출만 표시합니다.
- 수입 분석은 지출과 분리하고 예산 사용률이나 총지출에 포함하지 않습니다.
- 미분류 거래도 총지출에는 포함하며 카테고리 분석에서는 별도의 `미분류` 항목으로 표시합니다.

### 분석 내용

- 대분류별 지출을 원형 그래프와 금액·비율 목록으로 함께 표시합니다.
- 첫 버전의 카테고리 분석은 대분류까지만 집계하며 소분류별 분석은 제공하지 않습니다.
- 대분류를 선택하면 해당 대분류의 거래 목록을 표시합니다.
- 일별 지출 금액과 기간 누적 사용액을 함께 표시합니다.
- 이전 예산 기간과 총지출 및 카테고리별 증감액·증감률을 비교합니다.
- 최근 6개 또는 12개 예산 기간의 장기 추세를 전환해 볼 수 있습니다.

## 예산 알림

### 사용률 알림

- 공동 예산 사용률이 80%에 도달하면 두 사용자 모두에게 주의 알림을 보냅니다.
- 공동 예산을 모두 사용하거나 초과하면 두 사용자 모두에게 초과 금액을 알립니다.
- 본인 할당 예산의 80% 도달과 소진·초과 알림은 해당 사용자에게만 보냅니다.
- 상대방 개인 할당 예산 사용 알림은 보내지 않습니다.
- 공동 대분류 예산 알림은 두 사용자 모두에게 보내고 본인 대분류 예산 알림은 해당 사용자에게만 보냅니다.
- 한 거래로 80%와 100%를 함께 넘으면 가장 높은 단계만 알립니다.
- 사용률이 기준 이상인 상태에서는 거래가 추가돼도 같은 단계 알림을 반복하지 않습니다.
- 예산 변경이나 거래 수정·삭제로 사용률이 기준 아래로 내려간 뒤 다시 기준을 넘으면 같은 예산 기간에도 다시 알립니다.
- 나중에 등록한 거래가 현재 예산 기간에 속하면 일반 거래와 같은 예산 알림을 생성합니다.
- 종료된 과거 예산 기간에 거래를 등록하거나 수정해도 새 예산 알림을 생성하지 않습니다.
- 고정비나 할부 거래가 자동 등록되면서 기준을 넘으면 일반 거래와 같은 예산 알림을 생성합니다.

### 변경 알림

- 기간 전체 예산이나 멤버별 할당액을 변경하면 변경하지 않은 상대방에게 알립니다.
- 예비비를 본인 할당 예산이나 공동 예산으로 옮기면 두 사용자 모두에게 알립니다.
- 초기 범위에서는 앱 알림함으로만 제공하며 푸시, 문자와 이메일은 포함하지 않습니다.
- 알림을 선택하면 관련 대시보드, 예산 설정 또는 거래 상세로 이동합니다.

### 알림 설정

- 80% 주의 알림은 사용자가 끌 수 있습니다.
- 100% 도달·초과 알림은 끌 수 없습니다.
- 일요일 주간 예산 가이드는 사용자가 끌 수 있습니다.
- 공동 예산 변경 알림은 끌 수 없습니다.
- 설정은 사용자별로 적용하며 상대방의 알림 설정에 영향을 주지 않습니다.

### 알림함

- 알림은 앱 내부 알림함에서만 제공합니다.
- 읽지 않은 알림 개수를 표시합니다.
- 사용자는 알림을 개별적으로 읽거나 모두 읽음으로 처리할 수 있습니다.
- 사용자가 알림을 직접 삭제하는 기능은 제공하지 않습니다.
- 장부의 예산 기간에 속한 알림은 다음 예산 기간이 시작되면 알림함에서 자동으로 제거합니다.
- 다른 장부의 현재 예산 기간 알림은 함께 제거하지 않습니다.

### 주간 예산 가이드

- 매주 일요일 오후 9시에 사용자별 주간 예산 요약을 앱 알림함에 생성합니다.
- 한 주는 월요일부터 일요일까지로 보고 사용자의 현지 시간을 기준으로 계산합니다.
- 공동 예산 흐름과 본인 할당 예산 흐름만 포함하며 상대방 개인 예산은 제외합니다.
- 기본 주간 권장액은 현재 예산 기간의 예산을 기간 일수로 나눈 뒤 다음 주 중 같은 예산 기간에 포함되는 날짜 수만큼 계산합니다.
- 누적 사용액이 같은 시점의 누적 권장액을 초과하면 그 초과분을 다음 주 권장액에서 차감합니다.
- 28일인 예산 기간에 개인 할당 예산이 40만 원이고 첫 주에 15만 원을 사용했다면 다음 주 권장액은 5만 원입니다.
- 적게 쓴 금액은 여유분으로 표시하지만 소비를 유도하지 않도록 다음 주 권장액을 늘리지 않습니다.
- 초과분이 다음 주 기준액보다 크면 다음 주 권장액을 0원으로 표시하고 남은 초과분을 이후 계산에 반영합니다.
- 주간 권장액은 참고 정보이며 거래 저장을 제한하지 않습니다.
- 현재 예산 기간의 예산이 없으면 주간 권장액이나 알림을 생성하지 않습니다.
