# Information Architecture

이 문서는 [V1 Scope](../product/v1-scope.md)와 [User Flows](../product/user-flows.md)를 화면과 이동 구조로 연결합니다.
현재 프론트엔드 경로가 이 문서와 다르면 V1 구현 과정에서 점진적으로 교체합니다.

## 화면 구조

```text
공개 영역
  랜딩 / 카카오 로그인
  OAuth 콜백
  초대 링크 확인

보호 영역
  최초 닉네임 확정
  장부 선택
  공동 장부 생성
  홈 대시보드
    거래 추가 (드로어)
    알림함 (헤더 팝오버)
  가계부
    날짜순 거래 목록, 미분류 필터 칩
    거래 상세 / 수정 (모달)
    이미지 가져오기 검토 (모달)
  반복 거래 / 고정비 / 할부
  예산 설정
    현재 기간 예산
    다음 기간 사전 설정
    대분류 예산
  기간 종료 요약
  분석
  설정
    프로필
    공동 장부 초대와 멤버
    카테고리 관리
    알림 설정
```

## 주요 경로

| 경로 | 목적 |
| --- | --- |
| `/` | 제품 소개와 카카오 로그인 진입 |
| `/auth/kakao/callback` | OAuth 콜백과 원래 화면 복귀 |
| `/onboarding` | 최초 서비스 닉네임 확정 |
| `/dashboard` | 현재 예산 기간의 공동·본인 예산과 최근 거래 확인 |
| `/transactions` | 날짜순 거래 검색·필터와 상세 진입. 미분류 필터 칩 포함 |
| `/budget` | 현재·다음 예산 기간과 대분류 예산 설정 |
| `/periods/:startDate/summary` | 종료된 기간(시작일로 식별)의 예산 결과와 종료 요약 |
| `/analysis` | 대분류 지출, 소비 흐름과 기간 비교 |
| `/recurring` | 반복 지출, 고정비와 할부 관리 |
| `/ledgers/new` | 공동 장부 생성 |
| `/invitations/:token` | 초대 확인, 로그인 복귀와 수락·거절 |
| `/settings` | 프로필, 장부·멤버, 카테고리, 알림 설정을 모은 탭 화면 |

경로 이름은 구현 과정에서 현재 라우터 구조에 맞춰 조정할 수 있지만 화면의 책임과 진입 관계는 유지합니다.

다음은 독립 화면이 아니라 오버레이(모달·드로어·팝오버)로 제공합니다. 라우트를 갖지 않습니다.

| 기존에 화면으로 계획했던 것 | 실제 형태 | 진입 지점 |
| --- | --- | --- |
| 거래 추가 | 우측 드로어 560px | 홈을 포함한 모든 화면 헤더의 "거래 추가" 버튼 |
| 이미지 가져오기 검토 | 중앙 모달 | 가계부 화면 |
| 거래 상세 / 수정 | 가계부 화면 내 모달 | 가계부 목록 행 클릭 |
| 알림함 | 대시보드 헤더 팝오버(`top:78px; right:36px; width:436px`) | 대시보드 헤더 종 아이콘 (다른 화면에는 없음) |

미분류 거래 일괄 분류는 전용 화면 대신 가계부 화면의 "미분류" 필터 칩(`unclassified=true` 서버 파라미터)으로 제공합니다.

과거 라우트는 다음으로 리다이렉트합니다(`frontend/src/App.tsx`): `/transactions/import`, `/transactions/:transactionId`, `/transactions/uncategorized` → `/transactions`, `/notifications` → `/dashboard`, `/ledgers/:ledgerId/settings`, `/categories` → `/settings`.

기간 종료 요약(`/periods/:startDate/summary`)은 예산 화면의 하위 경로가 아니라 독립 화면입니다. 기간을 `periodId`가 아니라
시작일(`startDate`)로 식별하는데, 백엔드 `GET /api/ledgers/{ledgerId}/budget-periods/{startDate}/summary`가 그렇게 정의돼 있기 때문입니다.
**진입점은 기간 종료 알림의 딥링크 하나뿐입니다.** 예산 화면의 지난 기간 목록에서 들어가는 경로는 아직 없습니다.

## 주 이동 구조

데스크톱 사이드바의 주요 영역은 다음 다섯 가지입니다(`frontend/src/shared/ui/AppSidebar.tsx`, `frontend/src/components/layout/AppShell.tsx`).

- `홈`: 공동 예산, 본인 예산, 주간 가이드와 최근 거래
- `가계부`: 날짜순 거래 탐색, 검색과 필터, 미분류 필터
- `반복 거래`: 고정비·할부를 포함한 반복 지출 관리
- `예산 설정`: 현재·다음 기간과 대분류 예산 설정
- `분석`: 대분류 소비와 기간별 추세

거래 기록은 탭이 아니라 헤더의 "거래 추가" 버튼이 여는 전역 우측 드로어에서 시작합니다.
반복 거래는 보조 메뉴가 아니라 주 내비게이션 항목으로 승격되었습니다.
알림은 대시보드 헤더의 팝오버로, 설정은 사이드바 하단의 별도 항목으로 진입합니다.

## 장부 선택

- 기본 개인 장부는 항상 장부 선택기에 표시합니다.
- 공동 장부는 사용자가 생성하거나 참여한 장부만 표시합니다.
- 장부 선택기에서 새 공동 장부 생성으로 진입할 수 있습니다.
- 현재 장부를 바꾸면 홈, 가계부, 반복 거래, 예산 설정, 분석과 설정의 맥락이 함께 바뀝니다.
- 탈퇴하거나 내보내진 공동 장부의 참여 기간은 읽기 전용 기록으로 구분해 제공합니다.

## 정보 공개 원칙

- 홈에는 공동 예산과 로그인한 사용자의 예산만 표시합니다.
- 상대방 개인 거래는 홈과 분석에서 제외합니다.
- 상대방의 전체 할당·사용·잔액은 상세 화면에서 확인할 수 있습니다.
- 상대방 개인 거래는 상대방이 공유한 경우에만 상세 화면에 표시합니다.
- 공동 예산 거래는 두 사용자 모두 조회하고 수정할 수 있습니다.

## 화면 정의 기준

각 화면을 구현하기 전에 다음을 확인합니다.

- 화면 목적
- 가장 중요한 행동
- 필수 정보와 공개 범위
- 로딩·빈 상태·오류 상태
- 키보드와 터치 접근성
- 좁은 화면과 긴 텍스트
