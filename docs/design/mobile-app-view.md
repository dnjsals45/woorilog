# 모바일 웹 앱 뷰

확정 디자인(Crisp Calm V1)은 데스크톱 폭(사이드바 232px + 본문 최소 1080px) 기준입니다.
이 문서는 같은 디자인 시스템을 **모바일 웹 앱 뷰**로 확장한 규칙입니다.
색·반경·그림자·모션 값은 전부 기존 토큰을 그대로 씁니다. 여기서 새 값을 만들지 않습니다.

## 브레이크포인트

경계는 하나입니다.

| 폭 | 셸 |
| --- | --- |
| `< 1024px` | 모바일 앱 뷰 — 바텀 탭바 + 바텀시트 |
| `>= 1024px` | 데스크톱 뷰 — 좌측 사이드바 |

태블릿 세로(768~1023)도 앱 뷰로 넘깁니다. 사이드바 232px + 본문이 그 폭에서 성립하지 않습니다.

- CSS: `@media (width < 1024px)` (`frontend/src/styles/patterns/mobile-shell.css`)
- TS: `useIsMobileShell()` (`frontend/src/shared/lib/useIsMobileShell.ts`)

`useIsMobileShell()`은 **구조가 달라지는 곳**에서만 씁니다 — 사이드바 대신 탭바를 그린다든지,
모달 대신 시트를 연다든지. 스타일만 달라지는 곳은 CSS 미디어 쿼리로 처리합니다.

## 셸 구성

```text
[ 페이지 헤더 56px ]   AppHeader — 제목 + 아이콘 액션 (+ 기간 이동 줄)
[ 본문 (스크롤) ]
[ FAB 거래 추가 ]      우하단, 탭바 위 16px
[ 바텀 탭바 58px ]     홈 · 거래 내역 · 예산 · 분석 · 더보기
```

- 데스크톱 사이드바 5종을 그대로 탭으로 옮기면 설정·가계부 전환·도움말이 갈 곳이 없습니다.
  하루에 여러 번 오가는 네 화면만 탭에 두고, **자동 기록·가계부 전환·설정·도움말·로그아웃**은
  "더보기" 시트로 모았습니다. 자동 기록은 사라진 게 아니라 시트 맨 위에 있습니다.
- "거래 추가"는 데스크톱에서 화면 헤더 버튼입니다. 모바일에서는 FAB 하나가 그 역할을 합니다.
  화면 헤더에 같은 버튼을 또 두지 않습니다 (`AppHeader`의 `mobileActions`로 걷어냅니다).
- 하단 고정 요소는 `env(safe-area-inset-bottom)`을 더해 홈 인디케이터를 피합니다.

## 오버레이는 전부 바텀시트로

한 화면에서 오버레이마다 손이 가는 방향이 다르면 앱이 아니라 웹페이지처럼 느껴집니다.
모바일에서는 아래 넷이 모두 **화면 아래에서 올라오는 시트**가 됩니다.

| 데스크톱 | 모바일 |
| --- | --- |
| 거래 추가 우측 드로어 560px | 높은 바텀시트 (92dvh) |
| 중앙 모달 (`Modal`) | 바텀시트 (88dvh) |
| 알림함 우상단 팝오버 | 바텀시트 (80dvh) |
| 이미지 가져오기 모달 | 검토 단계는 전체 화면 |

- 손잡이(`.wl-sheet-grip`)를 잡아 끌어 닫습니다 — `useSheetDrag()`.
  **빠르게 튕겼거나**(속도 > 0.6px/ms) **28% 이상 내려왔으면** 닫고, 아니면 제자리로 돌아옵니다.
- 열려 있는 동안 뒤 화면은 스크롤되지 않습니다 — `useBodyScrollLock()`.
- 새 오버레이를 만들 때는 `Sheet` 컴포넌트를 먼저 검토합니다.

## 페이지 레이아웃 규칙

1. **인라인 `style`에 반응해야 하는 레이아웃을 두지 않습니다.**
   인라인 스타일은 미디어 쿼리로 덮을 수 없습니다. `gridTemplateColumns`, 고정 `width`,
   `flexDirection`처럼 폭에 따라 바뀌어야 하는 값은 `styles/patterns/**`의 클래스로 옮깁니다.
2. **줄어들어야 하는 상자에 `min-width: 0`을 줍니다.**
   flex·grid 안의 상자는 기본이 `min-width: auto`라 **min-content 아래로 줄어들지 않습니다.**
   띄어쓰기 없는 긴 문자열(URL, 아이디, 영수증 번호)이 들어가면 min-content가 그대로 커져
   부모를 뚫고 나가고, 그 줄의 오른쪽에 있던 것들이 화면 밖으로 밀립니다.
   가로로 나란히 놓는 줄에 `flex: none`인 자식이 있으면 **그 줄 자체에** `min-width: 0`이 필요합니다.
   자식에게만 준 `min-width: 0`은 자식에게만 걸립니다.
   그리드는 같은 뜻으로 `minmax(0, 1fr)`을 씁니다 — `1fr`만 쓰면 같은 문제가 납니다.
3. **한 글자씩 세로로 쌓인 글자는 "폭이 0까지 눌렸다"는 신호입니다.**
   그 옆에는 거의 항상 `flex: none`인 형제가 있습니다.
4. **좌우 2단은 모바일에서 위아래 1단으로** 세웁니다. 부가 정보(사이드 패널)가 아래로 갑니다.
5. **표는 카드 목록으로.** 4열 이상 표를 그대로 가로 스크롤시키지 않습니다.
   행 하나를 카드 하나로 바꾸고, 가장 중요한 두 값(이름·금액)을 첫 줄에 놓습니다.
   가로 스크롤이 정말 필요하면 `overflow-x: auto`를 표 자신이 아니라 감싼 래퍼에 겁니다.
6. **터치 타겟 최소 44px.** `.product-page button/a/summary`에 이미 걸려 있습니다.
7. **금액은 잘리기 전에 줄입니다.** `StatBlock`의 크기 단계는 `.wl-stat-amount--*`가 갖고
   420px 이하에서 한 단계 낮아집니다. 화면에서 인라인 `fontSize`로 큰 금액을 그리지 않습니다.
8. **입력 글자 크기는 16px 이상.** 그보다 작으면 iOS Safari가 포커스 때 화면을 확대합니다.
   `page-layout.css`가 760px 이하에서 이미 강제합니다.
9. **가로 스크롤 금지.** 390px에서 `document.body`가 가로로 밀리면 실패입니다.

## 페이지별 결정

| 화면 | 모바일 처리 |
| --- | --- |
| 홈 | 히어로 잔액 + 보조 지표 2열, 최근 거래와 사이드 패널을 위아래로 |
| 거래 내역 | 필터는 가로 스크롤 칩 줄, 목록은 날짜 그룹 카드, 상세는 시트 |
| 예산 설정 | 예산 나누기 슬라이더·입력을 1단으로, 저장 바는 탭바 위 |
| 자동 기록 | 표 → 카드 목록 |
| 분석 | 차트 폭은 컨테이너 기준, 도넛과 범례를 위아래로 |
| 기간 종료 요약 | 지표 2열, 카테고리 표 → 카드 목록 |
| 설정 | 탭 줄은 가로 스크롤, 폼은 1단 |
| 온보딩·가계부 생성·초대 확인 | 이미 좁은 카드형 — 여백만 줄임 |
| 랜딩 | 히어로 1단, 데스크톱 목업은 숨김 |

## 검증

```bash
cd frontend && npm run lint && npm run test && npm run build
```

화면 확인은 390 x 844(iPhone 14) 기준으로 하고, 다음을 봅니다.

- 가로 스크롤이 생기지 않는가
- 바텀 탭바·FAB이 본문 마지막 요소를 가리지 않는가
- 시트를 손잡이로 끌어 닫을 수 있고, 뒤 화면이 같이 밀리지 않는가
- 입력에 포커스를 줬을 때 화면이 확대되지 않는가
- `prefers-reduced-motion: reduce`에서 시트·FAB 애니메이션이 멈추는가
